# SCOUT Architecture

## Design principles

1. **Grounding over generation.** Every answer must trace to retrieved evidence; citations are
   validated, not decorative.
2. **Never trust the model with control.** LLMs propose; deterministic server code validates and
   executes. Analytics never executes model-written SQL.
3. **Never trust the documents.** Document text is untrusted input; prompt injection is neutralized
   before model calls.
4. **Raw data is immutable.** Parsers preserve raw cell/table values; normalization is additive
   metadata (`normalized_value`, `decimal_value`), never destructive.
5. **Crash-safe by default.** Idempotent jobs, atomic claims, durable queues, transactional
   outbox, dead-letter queues.

## Components

### 1. Ingestion (`app/ingestion`, `app/parsers`)

* **Format detection** (`detection.py`): signature + content heuristics (magic bytes, XML
  namespaces, JSON/CSV sniffing), not file extensions.
* **Canonical representation** (`canonical.py`): `CanonicalDocument` dataclasses — sections,
  elements (with provenance: page/sheet/line/locator), tables → rows → typed cells. Serializable
  to/from JSON for immutable version snapshots.
* **Table semantics** (`tables.py`): financial cell parsing (currencies, parentheses negatives,
  thresholds K/M/B/T, percents, European formats), header normalization, structural validation
  flags (ragged rows, mixed numeric columns, totals-row cross-checks).
* **Parsers**: `pdf.py` (Docling primary, PyMuPDF fallback with font-size heading heuristic and
  native table extraction), `docx.py`, `spreadsheets.py` (openpyxl + csv with delimiter
  detection), `pptx.py`, `structured_text.py` (ATX Markdown sections, code fences, lists).

### 2. Retrieval (`app/rag`, `app/ai`)

* **Chunker**: structure-aware — headings start chunks, tables stay whole (serialize with
  provenance annotation), code blocks unbroken, target ~1,500 chars with overlap; every chunk
  carries `content_hash` for idempotent re-indexing.
* **Hybrid retrieval**: PostgreSQL full-text search (tsvector with triggers, generated by the
  migration) and pgvector cosine top-K run in parallel.
* **Fusion**: Reciprocal Rank Fusion combines both ranked lists into one candidate set.
* **Reranker**: Qwen3 cross-encoder reorders candidates by query-evidence relevance; falls back
  gracefully to fused order when the model is unavailable.
* **Context expansion**: each evidence chunk pulls its parent section and neighboring context so
  the model sees complete tables/sections, not fragments.
* **Prompt guard**: document text is wrapped in demarcated, neutralized blocks; embedded
  instruction-like patterns are stripped before reaching Gemini.

### 3. Analytics (`app/analytics`)

* **Plan schema**: strict JSON — `filter` (comparators on columns), `group_by`, `aggregate`
  (SUM/AVG/MIN/MAX/COUNT), `sort`, `limit`. Nothing else is expressible.
* **Whitelister**: server-side validation of every operator, column reference, and literal;
  malformed/unknown fields hard-reject the plan.
* **Executor**: operates on the document's canonical table in memory with `Decimal` arithmetic —
  no SQL, no floats. Returns rows + provenance (sheet, source row indices).
* **Explanations**: an LLM narrates the deterministic result; the numbers themselves are computed
  by the executor, never the model.

### 4. Database (`app/db`, `alembic/`)

22 normalized tables: workspaces, users, documents, document_versions (immutable canonical
snapshots), document_sections/elements/tables/rows/cells, chunks, embeddings (pgvector),
conversations, messages, citations, reports, usage_events, outbox_events, processing_jobs.

* **RLS**: workspace-scoped policies on tenant tables; the API sets
  `SET LOCAL app.workspace_id` per request/transaction so enforcement is in-database.
* **FTS**: GIN indexes with trigger-maintained tsvectors on chunks/elements.
* **Outbox**: events written in the same transaction as state changes; a beat-scheduled dispatcher
  publishes to RabbitMQ with confirms and marks dispatched — at-least-once delivery.

### 5. Async pipeline (`workers/`)

* **Job claiming**: `UPDATE ... WHERE status IN ('queued','failed') RETURNING` — atomic; only one
  worker owns a job.
* **Idempotency**: reprocessing wipes prior versions/chunks/embeddings for the document before
  persisting; job stages report progress (download → detect → parse → persist → chunk → embed →
  finalize).
* **Retries**: capped attempts with exponential backoff + jitter; exhausted jobs go `dead` and the
  document flips to `failed`.
* **DLQ**: RabbitMQ dead-letter exchange for poison messages; a reaper requeues jobs stuck
  `running` > 30 min (worker crash detection).

### 6. AI services (`app/ai`)

* **Gemini client**: streaming + generate, retry with backoff, structured JSON mode for plans.
* **Embeddings**: Qwen3 local serving — batched, dimension-validated, retry-wrapped.
* **Reranker**: transformers cross-encoder with graceful fallback.

### 7. API (`app/api`, `app/schemas_*`, `app/services`)

FastAPI, JWT auth (Supabase-issued), workspace-scoped dependencies, SSE streaming chat,
  signed-URL uploads, per-request structured logging with request IDs. See `docs/api.md`.

### 8. Frontend (`frontend/`)

React 18 + TypeScript + Vite + Tailwind. Five primary views — Home (digest + quick ask),
  Discover (upload with progress, library, search, status polling, reprocess/delete), Chat
  (streaming answers + per-message citation chips), Insights (summarize/extract/compare/
  deterministic table analytics + report generation), Settings (account, workspace, usage).

## Data flow example

1. User drops `q4_report.xlsx` in Discover → signed-URL upload → storage.
2. `POST /documents/complete-upload` creates the document row + job, enqueues
   `scout.ingest_document`.
3. Worker claims the job, downloads bytes, detects XLSX, parses to canonical, wipes prior
   versions, persists sections/elements/tables/cells + a new immutable version snapshot, chunks,
   embeds, marks `ready`.
4. User asks "what drove the Q4 revenue drop?" in Chat.
5. Router → hybrid retrieval over this workspace's chunks → fusion → rerank → context expansion
   → prompt guard → Gemini stream → citation validation → SSE deltas + final citations.
6. A table question ("total revenue by region") routes to analytics: plan proposal →
   whitelist → Decimal execution → deterministic rows + provenance + explanation.
